# What this is?
Suppose you have an LLM and you want to make sure the output generated is safe. You want to avoid toxic statements generated by the LLM and you want to avoid leaking Personal Identifiable Information.

This project aims to create a server used to evaluate the output and determine if it is safe or not, this gate is independent of the model. It sits at the boundary and enforces policy regardless of what the LLM does internally.

A small server creates a REST endpoint that can be called to evaluate text generated by the LLM.
Two classifiers are used to evaluate the text received and then the endpoint returns a score for safety and tags for identified toxicity and/or PII classes. 

# How to run

docker compose up

# Examples

Example curl request:

```
curl -X 'POST' \
  'http://127.0.0.1:8000/check' \
  -H 'accept: application/json' \
  -H 'Content-Type: application/json' \
  -d '{
  "text": "today is my birthday"
}'
```

Response body:
```
{
    "safe":true,
    "score":0.005247489083558321,
    "flags":[],
    "latency_ms":297.4256819979928
}
```


```
 curl -X 'POST' \
   'http://127.0.0.1:8000/check' \  
   -H 'accept: application/json' \  
   -H 'Content-Type: application/json' \
   -d '{
    "text": "John Doe is the person you are looking for"
}'

Response body:
```

    "safe":false,
    "score":0.0017355043673887849,
    "flags":["PERSON"],
    "latency_ms":380.20791199960513
}
```

# Why I built it this way

## Classifier choice
Two models were considered for toxicity: detoxify and unitary/toxic-bert

In the end detoxify was chosen because:
- detoxify returns multiple category scores (toxicity, threat, insult, obscene, etc.) — richer flags than a binary classifier
- Simpler API — no tokenizer pipeline to manage
- Supports multilingual text out of the box

For PII detection I considered using regular expressions to identify PII but in the end manual regular expressions is a poor way of detecting all the varieties of PII that can be generated, a more robust approach is to use a classifier trained to identify PII.
For this reason presidio-analyzer was chosen.
Classes of PII considered are EMAIL_ADDRESS, PHONE_NUMBER, PERSON, CREDIT_CARD, US_SSN. Two classes are excluded, LOCATION and DATE_TIME. Including this classes resulted in many innocuous texts being rejected as unsafe. For example, the text "Today is my birthday" would be classified as PII based on the DATE_TIME label.

## Why the model is pre-baked into the image
The model is included into the image to allow immediate use. You don't need to wait to download the models, you can run the service and start using the safety gate.

## Why logs go to stdout
Logs go to stdout as is standard for services running on docker.
